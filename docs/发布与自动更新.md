# 发布与自动更新

仓库：https://github.com/Vintcet/jx3-network-diagnostics

下载：https://github.com/Vintcet/jx3-network-diagnostics/releases/latest

## 用户更新

0.4.0 起，工具在启动后自动检查 GitHub Releases。左下角显示版本、更新日期和作者，也可手动检查。发现新版后点击“下载并安装”，下载完成且签名校验通过后启动 Windows 安装程序，再启动新版。

正在采集或保存测试时禁止安装，下载和安装过程中禁止启动新的测试，前端和后端均检查。网络失败或签名错误不启动安装程序，可重试。检查更新仅访问发布服务，不上传诊断日志。

更新使用 NSIS 安装包。单文件版也可发起更新，完成后从开始菜单启动安装版；下载目录中的旧 EXE 不会替换，之后请使用安装版快捷方式。本机历史数据仍保存在原来的应用数据目录。

0.3.0 及更早版本没有自动更新功能，需要手动下载一次新版。GitHub 在当前网络不可达时，检查或下载可能失败；可稍后重试或从 Releases 手动下载。

## 正式发布

1. 同步修改 `package.json`、`package-lock.json`、`src-tauri/Cargo.toml` 和 `src-tauri/tauri.conf.json` 的版本号；运行 Cargo 更新 `src-tauri/Cargo.lock` 中的本包版本。
2. 修改 `package.json` 的 `releaseDate`，在 `CHANGELOG.md` 顶部填写相同版本与日期的更新记录，同步使用说明。左下角直接读取 `package.json` 的版本、日期、作者。
3. 运行 `npm run check`、Rust 测试和 lint，提交并推送代码。
4. 创建并推送标签，例如 `git tag v0.5.0`、`git push origin v0.5.0`。标签必须和版本号一致。
5. `.github/workflows/release.yml` 在 Windows 上测试、构建和签名，先创建草稿 Release，全部资产上传成功后才公开发布。失败时修复后重跑；已正式发布的版本不覆盖，使用新版本号。

首次配置或标签事件未触发时，可在 GitHub Actions 选择此工作流的“Run workflow”，填写已有版本标签。工作流检出该标签对应的源码，并检查它与应用版本一致。命令行也可使用 `gh workflow run release.yml --ref main -f tag=v0.4.1`。

发布文件包括带版本号的单文件 EXE、x64 安装包、安装包签名、`latest.json`、当前版本 SHA256 校验值和使用说明。更新地址固定为 Releases 的 `latest/download/latest.json`，清单中安装包使用具体版本标签地址。

## 签名密钥

GitHub Actions 需要两个仓库 Secret：

- `TAURI_SIGNING_PRIVATE_KEY`：Tauri 更新签名私钥的完整内容。
- `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`：私钥口令。

本地密钥保存在已被 Git 忽略的 `.secrets/updater.key`，口令在 `.secrets/updater.password`。请保留离线备份，不要提交到源码或上传为 Release 资产。公开配置中仅包含公钥。

`npm run build` 自动读取环境变量，或在没有环境变量时读取本地 `.secrets/`。公开源码检出后没有私钥，也能正常构建本地 EXE 和安装包，但不会生成签名和更新清单。不要通过替换正式公钥绕过缺失私钥：已发出的客户端必须用同一密钥签名的更新。

Tauri 更新签名用于客户端校验安装包，和 Windows Authenticode 代码签名不同。

## 本地构建结果

正式构建结束后，根目录包含 `jx3-network-diagnostics.exe`，`release/` 保留带版本号的 EXE 和安装包。若根目录 EXE 正在运行、无法覆盖，新版改放根目录 `jx3-network-diagnostics-版本号.exe`，构建输出会说明具体名称。
