# 报告与原始日志

每次测试创建独立的“日期时间＋区服”子文件夹。优先阅读或分享 `诊断报告.md`；可以直接复制文字给聊天助手，不要求对方安装本工具或读取原始日志。

| 文件 | 用途 |
| --- | --- |
| 诊断报告.md | 自包含的中文摘要：测试环境、结论、指标、具体阈值、异常实测值、时间、地址变化、卡顿标记、限制和后续问题 |
| report.html | 浏览器查看的报告 |
| report.json | 更完整的结构化结果；Markdown 对大量条目做了有说明的展示限制时可补充此文件 |
| samples.jsonl.gz | 精简后的原始记录，按行 JSON 并使用 gzip 压缩，供深入复核 |
| session.json | 测试配置和日志格式版本 |
| 本次测试说明.txt | 本次记录的时间、区服和文件用途 |

## 阈值

基线取同一目标、同一探测方式的成功延迟中位数 P50。网关的 ICMP 波动阈值为 `max(20 ms, P50×3+5 ms)`；其余 ICMP 目标为 `max(100 ms, P50×2+20 ms)`。

至少累计 10 个成功样本才启用判定。固定 10 秒窗口内至少有 3 条探测记录，其中至少 2 次超时或实际延迟严格大于阈值，才标记波动。超时记录等待上限，不伪装成实测延迟。TCP 建连独立统计，不套用该 ICMP 规则。

## 原始日志格式 compact-delta-v2

解压后的每一行都是一个 JSON 对象，包含 `type` 和 `data`。

- `format`：格式说明。
- `environment` / `environment_change`：开始环境或环境配置变化，不重复存储每秒完整配置。
- `process_definitions`：进程 PID、创建标识、名称和路径，在出现或变化时保存。PID 可能复用，应结合创建标识和记录时刻判断。
- `connection_changes`：与上一快照相比新增、移除的连接；连接状态变化会表现为旧行移除和新行加入。
- `sample`：每秒的接口速率、错误/丢弃计数、游戏 CPU/内存、非零观测流量及选中游戏/中转进程的流量。不可用状态独立记录；省略零流量行不证明网络完全没有活动。
- `flow_definitions`：为可见流端点分配 ID，保存进程、协议、本地和远端地址。
- `flow_bytes`：通过 ID 记录此窗口观测到的收发字节，不重复存储端点字符串。
- `probe`、`event`、`hop`、`endpoint_change`、`target_transition`：探测、事件、路径、地址变化和重点连接调整。

日志写入时持续刷新压缩流，正常结束时写入 gzip 尾部并同步落盘。意外断电或进程异常退出可能留下不完整尾部，部分解压工具会报错；已正常完成的报告不受影响。旧版未压缩的 `samples.jsonl` 不会自动删除，旧报告仍可读取和导出。

所有流量都是可观察到的数据，可能受事件交付延迟、权限、系统丢事件、代理和隧道影响。原始日志不包含网络正文。发送给 AI 前通常只需中文 Markdown 报告，不需要整份原始日志。
